Airflow 3 DAGs orchestrate dataset ingestion and team-controlled replay, queued candidate training, and maturity-aware monitoring/retraining. No fit call belongs in the shared scheduler. Use the staff-provided company gateway contract; retries must preserve batch/request identity. Production deployment needs human approval in CI.

`ingestion.py` implements the manual ingestion/replay DAG. Trigger it with a timezone-aware `as_of` parameter. Configure the Airflow connection `promiseops_feed` with the gateway origin in `extra.base_url` (or `host`) and the bearer feed token in `password`. Configure `promiseops_postgres` as a PostgreSQL connection to the team's database. The task calls `promiseops.data.sync_feed()`, which processes batches in contract order and delegates checksum, schema, quarantine, transaction, and idempotency behavior to the existing ingestion implementation. A failed batch fails the task; connection/network failures can retry safely because accepted batches are idempotent. The DAG is manual-only until a schedule and cutoff policy are explicitly chosen.

`training.py` implements a manual queued-training DAG. Supply `worker_image` as an immutable `@sha256` reference, the full `source_commit`, and timezone-aware `train_end`, `validation_end`, and `as_of` parameters. Before submission it checks that every batch in the gateway manifest for that `as_of` has a matching receipt/checksum in PostgreSQL. It posts to `/training` with `mode=train` and a request ID derived from the DagRun ID, so task retries reuse the same ID. The DAG observes the returned Job read-only and records the worker's final logs; it never creates or patches Kubernetes Jobs. Configure Airflow's `promiseops_jobs_kubernetes` connection with read-only access to `g02-jobs` and a usable auth method: `in_cluster=true` only when the Airflow task pod has a mounted service-account token, or `kube_config_path`/`kube_config` when credentials are provided through the connection. An available connection with empty extras is not sufficient when neither a service-account token nor a default kubeconfig exists. The Airflow task environment needs the Kubernetes provider and the project package. The worker trains and logs artifacts to MLflow; this DAG does not promote or deploy a model.

The full dataset is available via `GET /feed`. Choose chronological train/validation/test splits yourselves. For incremental ingestion, pass your chosen `as_of` to `GET /feed?as_of=...`; record it in each DAG run and use the same cutoff for predictions and monitoring. An unfiltered request returns all batches. Ingesting all rows at once is allowed, but feature/label queries must still respect their historical availability. No staff publication or clock advance is required.
